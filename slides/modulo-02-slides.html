Ejemplos LATAM

El dilema de los sistemas heredados

Sistemas heredados

  • Muchas universidades LATAM operan con sistemas de 15–20 años
  • No los reemplazan porque “funcionan”
  • Limitan crecimiento, fragmentan datos, crean dependencia
  • La decisión de migrar se encarece cada año que pasa

El costo oculto del “gratis”

  • Instituciones adoptan herramientas gratuitas como Moodle
  • Descubren tarde que no controlan los datos del estudiante
  • No pueden personalizar, dependen de terceros
¿Quién toma las decisiones tecnológicas estructurales? ¿El equipo directivo o el área de IT sola?

Decisión 1

Build vs Buy

Build (Construir)

  • Control total, diferenciación, propiedad de datos
  • Requiere equipo técnico, costos altos, tiempo
  • Conviene cuando el proceso es ventaja competitiva

Buy (Comprar)

  • Velocidad de implementación, menor riesgo inicial
  • Dependencia proveedor, limitaciones personalización
  • Conviene cuando el proceso es estándar

Ejemplo: Siglo 21 construyó su propio SIS (Proyecto Algarrobo) — escaló a 60,000+ estudiantes.

Comprá lo que es commodity. Construí lo que es tu ventaja competitiva.

Impacto financiero: Build = CAPEX + OPEX. Buy SaaS = OPEX predecible.

07 / 16
Decisión 2

Cloud vs On-Premise

☁️ Cloud

  • Escalabilidad, sin inversión inicial grande
  • Actualizaciones automáticas
  • Analogía: alquilar departamento

🏢 On-Premise

  • Control total, costos predecibles largo plazo
  • Analogía: comprar casa

Caso: Tec de Monterrey

Durante la pandemia la demanda se multiplicó 10x. Cloud (Azure) escaló elásticamente. Instituciones on-premise colapsaron.

Cloud no es lujo — es resiliencia operativa.

Financiero: Cloud convierte CAPEX en OPEX.

08 / 16
Decisión 3

Core vs Commodity

Core

Ventaja competitiva

  • Plataforma de aprendizaje personalizado
  • Motor de analítica de retención

Commodity

Necesarios pero no diferenciadores

  • Email
  • Videoconferencia
  • Sistema contable
⚠️
Anti-patrón
Invertir en personalizar commodities y usar soluciones genéricas para lo core.
09 / 16
Decisión 4

Velocidad vs Control

Priorizar Velocidad

Lanzar rápido, iterar
Aceptar deuda técnica corto plazo
Para validar hipótesis
Riesgo: acumulación de problemas

Priorizar Control

Planificar en detalle
Minimizar deuda técnica
Para sistemas críticos
Riesgo: parálisis por análisis
No hay respuesta correcta universal. Depende del momento, riesgo y reversibilidad.

Alineación

Tecnología alineada al negocio

01 Objetivos de negocio
02 → Capacidades necesarias
03 → Habilitadores tecnológicos
04 → Inversión y priorización
Ejemplo: Objetivo: reducir deserción del 42% al 25%. Capacidad: detectar estudiantes en riesgo. Habilitador: analítica predictiva LMS+SIS. Inversión: integración datos + modelo alertas + equipo intervención.
